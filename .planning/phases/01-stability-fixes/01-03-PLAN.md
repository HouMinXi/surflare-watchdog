  <action>
Investigate why api.ipify.org exits through VPN despite not being in proxy_rule_set. This is a read-only investigation -- SSH to N100 and gather data. No network disruption.

Steps to execute via SSH (ssh root@192.168.100.1):

1. Read the sing-box config dump to see actual routing rules:
   cat /tmp/singbox-config-dump.json | jq '.route.rules'
   Look for: rule 10 (catch-all tproxy-in -> direct), any rules that match api.ipify.org by domain or IP CIDR.

2. Check default_domain_resolver:
   cat /tmp/singbox-config-dump.json | jq '.route.default_domain_resolver'
   If the resolver routes through the proxy, DNS resolution itself goes through VPN, and the resolved IP might match an IP-based rule.

3. Check if api.ipify.org's IP falls within any proxy_rule_set ip_cidr entry:
   dig api.ipify.org +short   (on N100, or nslookup api.ipify.org 127.0.0.1)
   Then search the resolved IP in the config dump:
   cat /tmp/singbox-config-dump.json | jq '.route.rule_set[] | select(.tag=="proxy_rule_set") | .rules[] | select(.ip_cidr) | .ip_cidr[]' | grep -F <resolved_ip>

4. Check if api.ipify.org is in the domain_suffix of proxy_rule_set:
   cat /tmp/singbox-config-dump.json | jq '.route.rule_set[] | select(.tag=="proxy_rule_set") | .rules[] | select(.domain_suffix) | .domain_suffix[]' | grep -i ipify

5. Check DNS resolution path -- is api.ipify.org resolved by a DNS server that goes through VPN?
   cat /tmp/singbox-config-dump.json | jq '.dns'

6. Verify actual routing: does api.ipify.org actually exit through VPN?
   curl -s https://api.ipify.org   (should return VPN exit IP, not N100 WAN IP)
   curl -s --max-time 5 https://api.ipify.org   (if it times out, it's going direct and being blocked)

Record all findings. Determine which of the 4 hypotheses from RESEARCH.md Finding 4 is correct:
   (a) default_domain_resolver routes through proxy
   (b) stale config on N100 (config dump differs from analyzed config)
   (c) sing-box internal DNS resolves to an IP matching an ip_cidr rule
   (d) DNS cache hit on a previously-resolved IP

The investigation is complete when one of these is confirmed or all are ruled out.

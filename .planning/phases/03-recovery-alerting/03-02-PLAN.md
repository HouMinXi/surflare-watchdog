    REC-03 (partial): Pre-populate killswitch server_ips set from cached
    relay IPs before reconnect.

    Currently _update_killswitch_server_ips runs AFTER connect_vpn succeeds
    (L3978 area).  During connect, the killswitch output chain blocks relay
    traffic until server_ips is populated -- surflare connect --daemon's
    initial relay handshake depends on the 0xff mark rule (which is permanent
    since 5f3e109), but DNS resolution to find the relay IP goes through the
    killswitch output chain and may be blocked if the DNS server IP is not in
    server_ips or bypass_ipv4.

    Fix: Before calling surflare connect --daemon in connect_vpn(), if
    _diag_server_ips is non-empty (populated from previous successful
    connect), pre-populate the server_ips set:

    # Pre-populate server_ips from cache to avoid killswitch blocking relay DNS
    if [ -n "$_diag_server_ips" ] && \
       nft list set inet killswitch server_ips >/dev/null 2>&1; then
        local _cached_ips
        _cached_ips=$(echo "$_diag_server_ips" | tr ' ' ',')
        nft add element inet killswitch server_ips "{ $_cached_ips }" 2>/dev/null || true
        log "Pre-populated server_ips from cache: $_diag_server_ips"
    fi

    Place after _unarm_killswitch_output() (which removes output chain but
    preserves sets) and before surflare connect --daemon.

    This is additive: _update_killswitch_server_ips still runs after connect
    to refresh with current IPs (may have changed if relay rotated).
  </action>
  <verify>
    <automated>grep -q 'Pre-populated server_ips' surflare_watchdog.sh && bash -n surflare_watchdog.sh && echo PASS</automated>
  </verify>
  <done>server_ips pre-populated from cache before reconnect</done>

    REC-05: Create scripts/test_killswitch_forward.sh that verifies the
    killswitch forward chain is functioning correctly.

    The test runs on N100 via SSH.  It verifies:
    1. inet killswitch table exists
    2. forward chain exists with policy drop
    3. Required rules present: br-lan accept for bypass_devices,
       server_ips accept, mark 0x1 accept (VPN-routed), cn_domain_ips return
    4. Default policy is drop (LAN traffic blocked when VPN is down)
    5. bypass_devices set is non-empty (at least one device)

    The test is read-only (nft list only, no rule modifications).
    Exit 0 = all checks pass, exit 1 = any check fails.

    Script structure:
      #!/usr/bin/env bash
      set -euo pipefail
      N100="root@192.168.100.1"
      FAIL=0
      check() { if ! ssh "$N100" "$1"; then echo "FAIL: $2"; FAIL=1; else echo "OK: $2"; fi }

      check "nft list table inet killswitch >/dev/null 2>&1" "killswitch table exists"
      check "nft list chain inet killswitch forward 2>/dev/null | grep -q 'policy drop'" "forward chain policy drop"
      check "nft list chain inet killswitch forward 2>/dev/null | grep -q 'bypass_devices'" "bypass_devices rule"
      check "nft list chain inet killswitch forward 2>/dev/null | grep -q 'mark 0x00000001'" "VPN mark accept rule"
      check "nft list set inet killswitch bypass_devices 2>/dev/null | grep -qE '[0-9]+\.[0-9]'" "bypass_devices non-empty"

      exit $FAIL
  </action>

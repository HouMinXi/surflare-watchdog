    Server Chan API: POST https://sctapi.ftqq.com/${SENDKEY}.send
    Body: title=... and desp=...
    SendKey: stored in /etc/surflare/wechat.conf (chmod 600, gitignored)
    Format: SENDKEY=SCT... (single line, sourced by the function)

    Function design:
    _send_alert() {
        local _title="${1:-surflare alert}"
        local _body="${2:-}"
        local _conf="/etc/surflare/wechat.conf"
        local _sendkey

        [ -f "$_conf" ] || { log "WARN: alert skipped, $_conf not found"; return 1; }
        _sendkey=$(grep '^SENDKEY=' "$_conf" | cut -d= -f2-)
        [ -n "$_sendkey" ] || { log "WARN: alert skipped, SENDKEY empty"; return 1; }

        # Rate limiter: max 1 alert per 10 minutes
        local _now _last
        _now=$(date +%s)
        _last=${_alert_last_ts:-0}
        if [ $((_now - _last)) -lt 600 ]; then
            log "Alert rate-limited (last sent ${_last})"
            return 0
        fi
        _alert_last_ts=$_now

        # VPN-down fallback: use domestic DNS (223.5.5.5) and direct curl
        # (no proxy) since VPN may be down when we alert.
        # sctapi.ftqq.com is a CN service, reachable without VPN.
        # Update rate limiter state BEFORE forking (subshell cannot modify parent)
        # Background the curl so it does not block the reconnect path (10s worst case)
        (
            curl -sSf --noproxy '*' \
                --dns-servers 223.5.5.5 \
                --max-time 10 \
                --data-urlencode "title=${_title}" \
                --data-urlencode "desp=${_body}" \
                "https://sctapi.ftqq.com/${_sendkey}.send" \
                >/dev/null 2>&1 \
            && log "Alert sent: ${_title}" \
            || log "WARN: alert delivery failed: ${_title}"
        ) &
    }

    Place after check_vpn_local_state (L234), before _run_observability_probes.
    Add global rate limiter variable near L3830: _alert_last_ts=0

    NOTE: curl --dns-servers requires c-ares build.  N100's curl (OpenWrt) has
    c-ares.  If unavailable, fall back to system resolver (SmartDNS resolves
    CN domains directly).  Test on N100:
    curl --dns-servers 223.5.5.5 -sSf https://sctapi.ftqq.com/ 2>&1 | head -1
